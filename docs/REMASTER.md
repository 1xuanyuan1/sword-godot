# HD-2D 高清重构与离线 TTS

`release` 分支从旧版基线 Tag `v0.1.5` 开始，目标是在保留完整主线、地图拓扑、战斗与存档的前提下，建设 1920×1080 HD-2D 画面和离线角色语音。完整需求、数据模型、契约与十八章任务见 [hd2d-remaster-tts 需求目录](../.yulia/kb/requirements/hd2d-remaster-tts/spec/plan.md)。

## 不变边界

- 正式地图运行继续以 `TileMapLayer + PalTileMapWorld` 为唯一实现；CPU 合成只用于测试对照。
- 原版地图、RNG、FBP、战斗坐标和脚本语义继续使用 `320×200` 经典内容空间；它不再是高清模式的最终画布。
- 高清模式使用完整 1920×1080 画布。`PalTileMapWorld` 继续加载和同步正式地图，3D 视图只消费共享快照，不复制人物选帧、坐标、碰撞或事件规则。
- TTS 只使用离线生成的本地音频；客户端不包含 MiniMax Key，也不调用在线生成接口。
- `Data/`、`generated/`、嵌套 Private `sword-assets/` 和包含原版派生内容的移动验收包保持父仓 Git 忽略。

## 高清展示结构

`PalPresentationMetrics` 统一定义经典内容尺寸、1920×1080 高清画布、64px UI 安全边距、300px 对话区和整数缩放后的居中区域。`PalPresentationShell` 在 1080p 根视口内持续运行 320×200 `SubViewport`；经典回退区域为 `(160,40,1600,1000)`，不拉伸像素比例。后续高清画面按以下层次推进：

1. 经典兼容层保持 `320×200`，继续承担像素回归与缺失资源回退。
2. 高清世界采用 Godot 原生模块化 3D、固定 Camera3D、像素 Sprite3D、水墨远景、灯光、阴影、雾效和景深。
3. `PalWorldPresentationBuilder` 只选择一次队员编队位置、步态、剧情动作和 EventObject 帧，再由 `PalWorldTransform` 映射 3D 坐标并产出 `PalWorldPresentationSnapshot`；TileMap 与 HD 世界消费同一快照。
4. 高清 UI、字幕、立绘和语音状态使用 1080p 安全区，不改变经典世界坐标。
5. 每个章节都同时运行 TileMap 正式路径回归与 1080p 带窗口截图。

## 资产生产

- Bitto `nano-banana-2` 用于概念草案，`gpt-image-2` 用于定稿；提示词、模型、协议、尺寸和 SHA-256 随资源保存。
- Tripo3D 不接单独计费的开发者 API。需要独特静态建筑/道具时，可用 Studio 网站会员手动生成和导出 GLB，再经过轴向、比例、材质和面数检查后进入 Private 素材仓。
- Tripo 不生成整张可行走地图，也不替代 TileMap；主角/NPC 仍使用像素 Sprite3D。

## TTS 数据与运行时

MiniMax 只参与开发期离线资产生成：

1. `ScriptVM.dialog_round_ready` 在一整轮正文收齐时发出稳定的消息 ID 序列；说话人标题不进入朗读文本，分页保持独立轮次。
2. 本地生成清单保存正文消息 ID、说话人、音色、语速、文本哈希和输出文件；源文本变化后必须重新生成对应语音。
3. 运行时语音目录按消息 ID 序列查找音频，不从显示文字反推文件名。
4. 独立 `AudioStreamPlayer` 播放角色语音；对白推进、跳过和场景切换必须停止旧语音，不能占用 BGM 或八路原版音效池。
5. 系统菜单最终提供独立语音开关／音量。缺少语音文件时对白照常运行，不显示资源导入错误。
6. 第一章先完成角色选角、全对白生成、实际听检与游戏内回归，再扩展到后续章节。

## 发布约束

桌面公开包继续采用“玩家本地导入合法取得的 Data”模式。当前 Android 本地验收包会内置原版派生资源；只有在明确具备相应分发授权时，才能把这类 APK 上传为公开 Release 附件。
